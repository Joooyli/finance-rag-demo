# 页眉广告统一块清洗说明

更新日期：2026-10-26。本次按“混合解析完成后、跨页组装之前统一清洗一次”实施；不修改原始PDF，不在入库时再做另一遍正文删除。

## 1. 清洗位置与代码调用

```text
scripts.parse_pdf.main()
→ rag_pipeline.parse_document()
→ pdf_loader.extract_pdf_pages()
   ├─ 全部页面PyMuPDF预检与路由
   ├─ MinerU批次解析并等待返回
   ├─ 全部页面结果融合、按需Tesseract兜底
   ├─ header_filter.clean_document_blocks(records)  ← 全文统一调用一次
   └─ 生成页面text、检查最终质量、写pages.jsonl
→ document_assembler.assemble_document()
→ chunker.build_document_chunks()
→ 写产物、更新run.json、生成manifest.json
```

清洗时PyMuPDF、MinerU、Tesseract的最终区域块已齐全，能联合全文统计重复页眉；此后没有解析引擎再次把原PDF中的广告带回。清洗发生在页面正文和跨页逻辑块形成前，避免广告参与续段、章节标题、表格上下文及Embedding文本构造。

原先分散在PyMuPDF layout、MinerU适配和结果融合中的页眉/页脚删除已集中到这个入口。前面可以识别`header/footer/page_number`并在路由中忽略装饰类型，但不按删除开关提前排除；后续跨页组装和切块只消费最终`selected=true`的块，不再按类型另做一遍删除。关闭`HEADER_REMOVE`或`FOOTER_REMOVE`时，相应内容可沿用原类型保留到下游。

## 2. 方法职责

| 文件与方法 | 功能 |
|---|---|
| `app/header_filter.py::clean_document_blocks()` | 唯一清洗入口；统计跨页重复、识别广告、排除或拆分最终块、记录证据与事件 |
| `app/header_filter.py::_lines()` | 验证逐行文字、字符范围和bbox；只有能精确对应原块时才允许按行拆分 |
| `app/header_filter.py::_clean_context()` | 清理与已确认广告整行相同的title/caption/unit/section_path字段，原值留在provenance |
| `app/pdf_loader.py::_native_blocks()`、`_attach_native_lines()` | 提供或关联可核对的视觉页面行坐标；无可靠证据时不估算行位置 |
| `app/pdf_loader.py::extract_pdf_pages()` | 所有页融合/OCR结束后调用清洗，再构造页面正文及写页面日志 |
| `app/pdf_loader.py::_expected_content_types()` | 用文字及区域对应解除广告被误分类为公式的旧期待；真正正文公式丢失仍报质量问题 |
| `app/parse_quality.py::assess_result()` | 清洗后的结构/内容检查；纯广告页可保留为空正文页，未解决错误仍阻断质量通过 |
| `app/parse_log.py::config_snapshot()` | 把实际清洗规则写入配置快照 |
| `app/rag_pipeline.py::_pipeline_identity()` | 清洗模块代码与配置参与流水线指纹，规则改变后产生不同处理版本 |

## 3. 识别规则与误删保护

启用`HEADER_REMOVE=true`时，按以下证据处理：

1. **明确页眉类型**：最终块被引擎标记为`header`且没有跨入正文的混合证据时，统一排除并记录`classified_header`；大块跨入正文时仍需逐行分离或标记待核对，不仅凭类型删除整块。
2. **已知广告文本**：候选整行/整块位于顶部范围，完整匹配配置正则时排除；不是在整篇正文中搜索后全局替换。
3. **跨页重复文本**：短文本处于顶部且位置一致，达到重复页数及比例阈值时识别为页眉候选。比较时规范空白和字形差异，不把不同金额、日期、页码中的数字泛化成同一个文本。

默认顶部候选范围为页面高度的12%，它只限定候选区域，**不代表裁掉顶部12%**。普通章节标题不因靠近顶部而删除；`heading`不使用自动重复文本规则，只有明确广告规则等证据才能处理。表格与公式属于受保护结构，疑似混入广告时保留结构并标记待核对，不直接截断。

同一句广告出现在正文其他位置时保留。重复文字位置不一致、不足3页或不足全文60%时，不仅凭“重复”自动删除。

### 广告与正文位于同一块

- 有逐行文本、准确字符范围与视觉bbox时，只排除广告行；连续保留的正文行生成新块ID。
- 原父块保留为`selected=false`，原文不覆盖；子块保留`provenance.source_block_id`、`source_char_range`和原文引用。
- 原始Markdown的`raw_pos`不能继续当成子块偏移；原偏移转存为来源信息。
- 无法可靠分离时保留该块，标记`needs_review`及`advertising_header_not_separable`等问题，禁止以整块删除来猜测正文边界。

扫描页或MinerU输出没有可靠行几何时同样遵循上述规则；不能按文本行数均分bbox来制造坐标。

## 4. 实际配置文件是 `.env`

运行配置统一写在项目根目录`.env`；`.env.example`仅提供模板，程序不读取模板作为运行配置。

```dotenv
HEADER_REMOVE=true
FOOTER_REMOVE=false

# 只限定顶部候选范围，不裁页。
HEADER_FILTER_TOP_RATIO=0.12
HEADER_REPEAT_MIN_PAGES=3
HEADER_REPEAT_MIN_RATIO=0.6
HEADER_REPEAT_POSITION_TOLERANCE=0.02

# JSON数组，每个字符串是完整匹配候选行/块的正则。
HEADER_AD_PATTERNS='["高顿学术中心独家研发学习资料[，,]未经许可[，,]不得私自传播[。.]?"]'
```

重复位置容差按归一化页面坐标计算，默认每个bbox坐标差不超过0.02。显式广告正则应按实际原页文字配置；不要写成`.*`这类宽泛规则。上述已知广告规则已补入当前项目`.env`，既有配置和密钥保留。修改后重新执行CLI；已启动API需要重启。

## 5. 原始证据、日志与最终正文

| 位置 | 清洗后的含义 |
|---|---|
| 原始PDF、`raw/` | 保留完整原件和引擎原始输出，允许仍包含广告 |
| `blocks.jsonl`及页面内`blocks` | 保留被排除的广告、原混合父块及保留子块；用`selected`区分正文与证据 |
| `pages.jsonl`的`text` | 从清洗后选中块重新生成，不含已确认并排除的广告 |
| `pages.jsonl`的`cleaning` | 规则版本、完成状态、排除动作、bbox、文本预览及上下文字段清理记录 |
| `logical_blocks.jsonl` | 仅由清洗后的选中块构造，广告不参与章节路径和跨页合并 |
| `chunks.jsonl` | `text/embedding_text`来自清洗后的逻辑块；保留来源块引用 |
| `events.jsonl`、`app.log` | `header_excluded`记录排除页/块/规则，`cleaning_completed`记录每页统计 |

因此，“正文没有广告”不等于原始日志文件中完全找不到广告。保留原文是为了回看删除依据。`cleaning.excluded`统计排除动作，混合块按广告行记录；不能一概解释为删除了多少个原始PDF块。

只有全文融合/OCR和统一清洗完成后才写最终页面记录；引擎开始/完成等事件仍在执行过程中即时记录。某页清理后只有广告、没有正文时保留原物理页，避免后续把不相邻页面当成相邻页；已有识别失败或存疑问题不会因此被清空。

## 6. 重新生成并替换旧索引

已解析或已入库记录不会被本次代码修改自动清洗。使用新规则重新解析，按新run检查后再确认和入库：

```powershell
.\.venv\Scripts\python.exe -m scripts.parse_pdf '.\data\source\frm_notes.pdf'

$runId = '替换为本次新输出的run_id'
.\.venv\Scripts\python.exe -m scripts.review_parsed --run-id $runId --show-all

# 实际检查者核对后执行；存疑记录无法批准。
.\.venv\Scripts\python.exe -m scripts.review_parsed --run-id $runId --reviewer '实际检查者' --approve
.\.venv\Scripts\python.exe -m scripts.index_parsed --run-id $runId
```

同一CLI来源路径保留同一doc_id，新索引核验成功后替换该文档的活动版本，旧快照和原始证据保留。API更新已有文档需显式传原doc_id；省略时新增文档，不会替换旧活动文档。不要直接编辑旧chunks或manifest伪造清洗后的审阅依据。

## 7. 验证边界

自动测试覆盖单次调用顺序、PyMuPDF/MinerU/Tesseract来源、重复顶部广告、正文同词保留、同块广告行拆分、不能安全分离时待核对、关闭开关保留、原始证据、纯广告物理页及密封来源引用。

本轮完整测试`python -m pytest -q`为144项通过，包含31项统一清洗及应用链路测试。另对真实`frm_notes.pdf`原第3、5、28页执行PyMuPDF预检和统一清洗，每页固定广告被排除，正文和原始证据保留；产物使用临时目录，未执行新的MinerU推理、Embedding或正式库写入。

本轮不以单元测试代替整份财务PDF的人工准确率核验；检查时应逐页对照页眉与正文边界，特别关注封面、章节首页及顶部表格。真实财务数据的完整识别效果和正式向量库替换需在新产物检查通过后执行。
